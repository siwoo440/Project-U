# 프로젝트 U 제작·보관·건축 규칙

## 1. 문서 목적

이 문서는 프로젝트 U의 제작, 제작 시설, 보관함, 건축 연결, 기능성 가구, 철거 및 저장 규칙을 정의한다.

48~54일차 구현은 이 문서의 규칙을 기준으로 진행한다.

## 2. 데이터 ID 규칙

| 데이터 종류 | 접두사 | 예시 |
|---|---|---|
| 일반 제작법 | `recipe_` | `recipe_axe` |
| 건축 데이터 | `structure_` | `structure_wood_wall` |
| 제작 시설 | `facility_` | `facility_workbench` |
| 보관함 종류 | `storage_` | `storage_small_chest` |
| 해금 조건 | `unlock_` | `unlock_basic_workbench` |

### 2.1 공통 ID 작성 규칙

1. ID에는 영문 소문자, 숫자, 밑줄만 사용한다.
2. ID는 같은 데이터 종류 안에서 중복될 수 없다.
3. 저장 데이터에 사용된 ID는 이후 변경하지 않는다.
4. 화면 표시 이름과 저장 ID는 별도로 관리한다.
5. 삭제한 ID를 다른 데이터에 다시 사용하지 않는다.
6. 배열 순서나 파일 이름을 저장 ID로 대신하지 않는다.

### 2.2 기존 ID 유지 목록

| 대상 | ID |
|---|---|
| 도끼 제작법 | `recipe_axe` |
| 곡괭이 제작법 | `recipe_pickaxe` |
| 모닥불 | `structure_campfire` |
| 나무 바닥 | `structure_wood_floor` |
| 나무 벽 | `structure_wood_wall` |
| 침낭 | `structure_sleeping_bag` |

기존 ID는 저장 데이터와 기존 에셋의 호환성을 위해 변경하지 않는다.

## 3. 제작법 해금 규칙

제작법은 기본 해금, 설계도 해금, 퀘스트 해금으로 구분한다.

| 해금 종류 | 처리 방식 |
|---|---|
| 기본 해금 | 새 게임 시작부터 사용 가능 |
| 설계도 해금 | 설계도 아이템 사용 시 영구 해금 |
| 퀘스트 해금 | 지정 퀘스트 보상 수령 시 영구 해금 |

### 3.1 초기 제작법 상태

| 제작 대상 | 시작 상태 |
|---|---|
| 도끼 | 기본 해금 |
| 곡괭이 | 기본 해금 |
| 모닥불 | 기본 해금 |
| 나무 바닥 | 기본 해금 |
| 나무 벽 | 기본 해금 |
| 침낭 | 기본 해금 |

### 3.2 해금 저장 규칙

1. 해금된 제작법은 `recipeId` 목록으로 저장한다.
2. 제작법 이름이나 배열 번호를 저장값으로 사용하지 않는다.
3. 한번 해금된 제작법은 제작 시설을 철거해도 유지한다.
4. 제작법 해금 여부와 제작 시설 보유 여부는 별도로 검사한다.
5. 알 수 없는 `recipeId`는 해금 목록에서 제외하고 오류를 출력한다.

## 4. 제작 시설 규칙

| 시설 | 용도 |
|---|---|
| 맨손 제작 | 기본 도구와 간단한 생존품 |
| 작업대 | 가공 도구, 장비, 건축용 부품 |
| 모닥불 | 음식 조리 |
| 상급 작업대 | 후반 장비와 복잡한 부품 |

초기 수직 슬라이스에서는 맨손 제작, 작업대, 모닥불만 사용한다.

### 4.1 시설 판정 규칙

1. 맨손 제작법은 장소와 관계없이 사용할 수 있다.
2. 작업대 제작법은 작업대 UI에서만 표시한다.
3. 모닥불 조리는 기존 `CampfireCookingStation`에서 처리한다.
4. 필요한 시설을 사용할 수 없으면 제작 버튼을 비활성화한다.
5. 시설 철거로 이미 해금된 제작법이 잠기지 않는다.
6. 제작법 해금과 시설 요구 조건을 별도로 검사한다.
7. 제작 시설마다 고유한 `facilityId`를 사용한다.

## 5. 제작 성공·실패 규칙

제작은 재료와 결과 아이템을 보관할 공간이 모두 확보된 경우에만 실행한다.

### 5.1 제작 처리 순서

1. 제작법 해금 여부를 확인한다.
2. 필요한 제작 시설을 사용할 수 있는지 확인한다.
3. 모든 제작 재료의 보유 수량을 확인한다.
4. 결과 아이템을 넣을 인벤토리 공간을 확인한다.
5. 모든 조건이 충족된 경우에만 재료를 소비한다.
6. 재료 소비가 완료되면 결과 아이템을 지급한다.
7. 처리 도중 실패하면 소비한 재료와 지급한 결과를 원래 상태로 되돌린다.

### 5.2 제작 실패 규칙

다음 조건에서는 제작을 실행하지 않는다.

- 제작법이 잠겨 있음
- 필요한 제작 시설을 사용할 수 없음
- 필요한 재료가 부족함
- 결과 아이템을 넣을 공간이 부족함
- 제작법 데이터가 누락됨
- 재료 또는 결과 아이템 데이터가 누락됨

제작에 실패하면 재료를 일부라도 소비하지 않는다.

### 5.3 건축 제작 규칙

1. 건축물 완성품은 인벤토리에 생성하지 않는다.
2. 건축 미리보기 단계에서는 재료를 소비하지 않는다.
3. 설치 위치가 유효하고 설치가 확정될 때 재료를 소비한다.
4. 재료 소비에 실패하면 건축물을 생성하지 않는다.
5. 건축물 생성에 실패하면 소비한 재료를 되돌린다.
6. 설치 취소 시 재료를 소비하지 않는다.

## 6. 보관함 규칙

초기 보관함은 소형 보관함과 대형 보관함으로 구분한다.

| 보관함 종류 | 저장 ID | 슬롯 수 | UI 배열 |
|---|---|---:|---|
| 소형 보관함 | `storage_small_chest` | 12칸 | 4열 × 3행 |
| 대형 보관함 | `storage_large_chest` | 24칸 | 6열 × 4행 |

보관함에는 별도의 무게 제한을 적용하지 않는다.

### 6.1 아이템 보관 규칙

1. 각 슬롯에는 한 종류의 아이템만 저장한다.
2. 아이템 최대 중첩 수량은 기존 `ItemData.MaximumStack` 값을 사용한다.
3. 도구와 장비는 기존 아이템 데이터에 따라 최대 1개만 중첩한다.
4. 동일한 아이템을 이동하면 기존 아이템 묶음에 먼저 합친다.
5. 최대 중첩 수량을 초과한 아이템은 원래 슬롯에 남긴다.
6. 서로 다른 아이템을 겹치면 두 슬롯의 아이템을 교환한다.
7. 이동할 공간이 부족하면 아이템 이동을 취소한다.
8. 이동에 실패한 아이템을 바닥에 자동으로 버리지 않는다.
9. 빈 슬롯 사이의 이동도 슬롯 위치 변경으로 처리한다.

### 6.2 보관함 UI 규칙

1. 한 번에 하나의 보관함만 열 수 있다.
2. 보관함 UI에는 플레이어 인벤토리와 보관함 슬롯을 함께 표시한다.
3. 두 영역 사이에서 드래그 앤 드롭으로 아이템을 이동한다.
4. 보관함을 닫아도 아이템 슬롯 순서를 유지한다.
5. 보관함을 다시 열 때 아이템을 자동으로 정렬하지 않는다.
6. 보관함과의 상호작용 거리를 벗어나면 UI를 닫는다.
7. 사망하거나 수면을 시작하면 보관함 UI를 닫는다.
8. 건축 모드에 진입하면 보관함 UI를 닫는다.
9. 다른 보관함을 열면 기존 보관함 UI를 먼저 닫는다.
10. 보관함 UI가 열려 있는 동안 플레이어 시점 입력을 제한한다.

## 7. 보관함 저장 규칙

보관함 데이터는 설치된 건축물의 고유한 `StructureId`와 연결하여 저장한다.

### 7.1 저장 항목

| 저장 항목 | 내용 |
|---|---|
| `structureId` | 설치된 보관함 건축물의 고유 ID |
| `storageTypeId` | 보관함 종류 ID |
| `slotIndex` | 아이템이 저장된 슬롯 번호 |
| `itemId` | 저장된 아이템의 고유 ID |
| `quantity` | 저장된 아이템 수량 |

### 7.2 저장 처리 규칙

1. 보관함마다 고유한 `structureId`를 사용한다.
2. 저장할 때 현재 슬롯 번호와 아이템 위치를 유지한다.
3. 빈 슬롯을 포함한 전체 슬롯 구조를 유지한다.
4. 불러올 때 아이템을 자동으로 정렬하지 않는다.
5. 불러온 아이템 수량은 해당 아이템의 최대 중첩 수량을 초과할 수 없다.
6. 같은 `structureId`가 중복되면 저장 데이터 오류로 처리한다.
7. 보관함 슬롯 수보다 큰 `slotIndex`는 손상된 데이터로 처리한다.
8. 존재하지 않는 `itemId`는 복원하지 않고 오류를 출력한다.
9. 존재하지 않는 `storageTypeId`는 해당 보관함 복원을 중단한다.
10. 보관함이 철거되면 연결된 보관 데이터도 제거한다.

### 7.3 철거 전 보관함 검사

1. 보관함에 아이템이 남아 있으면 철거할 수 없다.
2. 모든 슬롯이 비어 있는 경우에만 철거할 수 있다.
3. 보관함 UI가 열려 있는 동안에는 철거할 수 없다.
4. 철거가 완료되면 해당 `structureId`의 저장 데이터를 제거한다.

## 8. 건축물 분류 규칙

건축물은 배치 방법과 구조적 역할을 별도로 구분한다.

### 8.1 배치 방법

현재 `BuildPlacementType`의 값은 다음과 같다.

| 배치 종류 | 숫자 값 | 용도 |
|---|---:|---|
| `Floor` | 0 | 격자 바닥 배치 |
| `Wall` | 1 | 격자 가장자리 벽 배치 |
| `Free` | 2 | 자유 위치 배치 |

기존 데이터와 저장 호환성을 위해 `BuildPlacementType`의 이름과 숫자 값을 변경하지 않는다.

### 8.2 건축 부품 분류

| 부품 종류 | 역할 |
|---|---|
| `Foundation` | 지형 위에 설치되는 건축 기초 |
| `Floor` | 기초 위에 설치되는 바닥 |
| `Wall` | 기초 또는 바닥의 가장자리에 설치되는 벽 |
| `Furniture` | 지형이나 바닥 위에 설치되는 가구 |
| `Roof` | 벽 또는 지붕 연결점에 설치되는 지붕 |

### 8.3 분류 적용 규칙

1. `BuildPlacementType`은 배치 위치와 회전 계산에 사용한다.
2. 건축 부품 분류는 지지 관계와 철거 가능 여부 판정에 사용한다.
3. 배치 방법과 건축 부품 분류를 하나의 값으로 합치지 않는다.
4. 건축물마다 하나의 대표 부품 분류를 지정한다.
5. 저장 데이터에는 건축 데이터 ID를 저장하고 숫자 배열 위치를 사용하지 않는다.
6. 현재 존재하는 건축 데이터의 `BuildPlacementType` 숫자 값은 변경하지 않는다.
7. 새로운 부품 분류를 추가하더라도 기존 배치 종류의 숫자 값은 유지한다.

## 9. 건축물 연결과 지지 규칙

건축물은 기존 `BuildGridArea`의 1미터 격자를 기준으로 배치한다.

### 9.1 기본 연결 순서

건축물의 기본 연결 순서는 다음과 같다.

```text
지형
↓
기초
↓
바닥
↓
벽·가구
↓
지붕

9.2 기초 설치 규칙
기초는 지형의 유효한 격자 중앙에 설치한다.
같은 격자에는 하나의 기초만 설치할 수 있다.
기초가 지형에서 과도하게 떠 있으면 설치할 수 없다.
기초가 지형에 과도하게 묻히면 설치할 수 없다.
기초 설치 위치에 다른 건축물이나 장애물이 있으면 설치할 수 없다.
기초는 상단에 바닥 또는 가구용 연결점을 제공할 수 있다.
기초가 다른 건축물을 지지하고 있으면 철거할 수 없다.
9.3 바닥 설치 규칙
바닥은 기초의 상단 연결점에 설치한다.
하나의 연결점에는 하나의 바닥만 설치할 수 있다.
바닥은 1미터 격자에 맞춰 배치한다.
바닥의 기본 회전은 90도 단위를 사용한다.
지지할 기초가 없는 공중에는 설치할 수 없다.
바닥은 벽, 가구 또는 지붕을 위한 연결점을 제공할 수 있다.
바닥이 다른 건축물을 지지하고 있으면 철거할 수 없다.
9.4 벽 설치 규칙
벽은 기초 또는 바닥의 네 가장자리 연결점에 설치한다.
벽은 90도 단위로 회전한다.
이미 벽이 설치된 연결점에는 다른 벽을 설치할 수 없다.
지지할 기초나 바닥이 없으면 설치할 수 없다.
벽이 다른 건축물과 충돌하면 설치할 수 없다.
벽은 지붕이나 상위 벽을 위한 연결점을 제공할 수 있다.
벽이 다른 건축물을 지지하고 있으면 철거할 수 없다.
9.5 가구 설치 규칙
가구는 지형 또는 바닥 표면에 설치한다.
가구는 BuildRecipeData에 설정된 회전 간격을 사용한다.
가구의 전체 바닥 면적이 유효한 표면 위에 있어야 한다.
가구가 다른 건축물이나 장애물과 충돌하면 설치할 수 없다.
경사가 허용 범위를 초과하면 설치할 수 없다.
기능성 가구는 설치 완료 후에만 상호작용할 수 있다.
가구를 지지하는 바닥이 철거되면 안 되므로 해당 바닥 철거를 차단한다.
9.6 지붕 설치 규칙
지붕은 벽 또는 지붕 전용 연결점에 설치한다.
지붕은 90도 단위로 회전한다.
지지할 벽이나 연결점이 없으면 설치할 수 없다.
이미 사용 중인 연결점에는 추가로 설치할 수 없다.
지붕이 다른 지붕을 지지하고 있으면 먼저 상위 지붕을 철거해야 한다.
9.7 연결점 규칙

각 연결점은 다음 정보를 가진다.

항목	내용
연결점 ID	건축물 내부에서 연결점을 구분하는 고유 ID
연결 가능 부품	해당 위치에 설치할 수 있는 부품 종류
연결 위치	건축물 기준 로컬 위치
연결 회전	설치될 건축물의 기준 회전
사용 상태	다른 건축물이 현재 사용 중인지 여부

적용 규칙은 다음과 같다.

연결점 ID는 같은 건축물 안에서 중복될 수 없다.
연결점 ID는 저장 데이터에 사용된 이후 변경하지 않는다.
사용 중인 연결점에는 새로운 건축물을 설치할 수 없다.
연결된 건축물이 철거되면 연결점을 다시 사용할 수 있다.
연결할 수 없는 부품 종류는 해당 연결점에 설치하지 않는다.
배치 미리보기 단계에서는 연결점을 점유하지 않는다.
설치가 확정된 순간에만 연결점을 사용 상태로 변경한다.
9.8 건축 연결 저장 항목

건축 연결 상태는 다음 정보를 저장한다.

저장 항목	내용
structureId	현재 건축물의 고유 ID
supportStructureId	현재 건축물을 지지하는 건축물의 고유 ID
connectionPointId	사용한 연결점 ID
position	월드 위치
rotation	월드 회전
buildRecipeId	건축 데이터 ID

저장 및 불러오기 규칙은 다음과 같다.

지형에 직접 설치된 건축물은 supportStructureId를 비워 둔다.
연결 건축물은 지지 건축물보다 나중에 복원한다.
존재하지 않는 지지 건축물을 참조하면 해당 건축물 복원을 중단한다.
존재하지 않는 연결점 ID를 참조하면 오류를 출력한다.
같은 structureId가 중복되면 저장 데이터 오류로 처리한다.
불러오기가 완료된 후 전체 지지 관계를 다시 검사한다.
10. 기능성 가구 규칙

기능성 가구는 설치된 이후 플레이어와 상호작용할 수 있는 건축물이다.

10.1 기능 종류

10.2 공통 구성 규칙
모든 기능성 가구에는 PlacedBuildObject를 연결한다.
모든 기능성 가구는 고유한 StructureId를 가진다.
하나의 기능성 가구에는 하나의 대표 기능만 지정한다.
상호작용은 기존 PlayerInteractor의 거리 판정을 사용한다.
건축 미리보기 상태에서는 상호작용할 수 없다.
건축 설치가 완료된 이후에만 기능을 활성화한다.
건축 모드에서는 기능성 가구와 상호작용할 수 없다.
플레이어가 사망한 상태에서는 기능을 사용할 수 없다.
기능별 저장 데이터는 같은 StructureId와 연결한다.
서로 다른 기능의 저장 데이터는 별도로 관리한다.
10.3 보관함 기능
상호작용하면 보관함 UI를 연다.
보관함 UI에는 플레이어 인벤토리와 보관함 슬롯을 표시한다.
보관함에 아이템이 있으면 철거할 수 없다.
보관함 UI가 열려 있으면 철거할 수 없다.
저장 데이터는 보관함의 StructureId와 연결한다.
10.4 작업대 기능
상호작용하면 작업대 제작 UI를 연다.
작업대 전용 제작법만 표시한다.
해금되지 않은 제작법은 제작할 수 없다.
제작법 해금과 작업대 사용 가능 여부를 별도로 검사한다.
제작 처리 중에는 작업대를 철거할 수 없다.
작업대를 철거해도 해금된 제작법은 유지한다.
10.5 조명 기능
상호작용할 때마다 조명을 켜거나 끈다.
현재 조명 상태를 저장한다.
불러오기 후 저장된 조명 상태를 복원한다.
조명 기능이 비활성화된 경우 광원을 끈다.
조명 상태와 건축물 배치 상태를 같은 StructureId로 연결한다.
10.6 휴식 기능
침낭 상호작용 시 수면 가능 조건을 확인한다.
수면 중에는 침낭을 철거할 수 없다.
침낭을 부활 지점으로 등록할 수 있다.
등록된 침낭을 철거하면 해당 부활 지점 등록을 해제한다.
수면과 부활 지점 정보는 침낭의 StructureId와 연결한다.
존재하지 않는 침낭을 부활 지점으로 사용할 수 없다.
10.7 조리 기능
모닥불 상호작용 시 조리 UI를 연다.
조리법과 필요한 재료를 확인한 후 조리를 시작한다.
조리 중인 재료, 남은 시간과 완성 결과를 저장한다.
조리 중에는 모닥불을 철거할 수 없다.
완성된 음식이 남아 있으면 철거할 수 없다.
결과 아이템을 회수한 이후 철거할 수 있다.
조리 상태는 모닥불의 StructureId와 연결한다.
11. 철거와 재료 반환 규칙

건축물 철거 시 설치에 사용한 재료의 일부를 플레이어 인벤토리로 반환한다.

11.1 기본 반환 계산
반환 수량 = 설치 필요 수량 × 철거 반환 비율
최종 반환 수량 = 반환 수량의 소수점 이하 내림

기본 철거 반환 비율은 0.5, 즉 50%로 설정한다.

11.2 반환 계산 예시
설치 필요 수량	반환 비율	계산 결과	최종 반환
10개	50%	5	5개
5개	50%	2.5	2개
3개	50%	1.5	1개
1개	50%	0.5	0개

최종 반환 수량이 0개인 재료는 반환 목록에서 제외한다.

11.3 철거 차단 조건

다음 조건 중 하나라도 해당하면 철거할 수 없다.

다른 건축물을 지지하고 있음
연결된 상위 건축물이 존재함
보관함에 아이템이 남아 있음
보관함 UI가 열려 있음
작업대에서 제작이 진행 중임
모닥불에서 조리가 진행 중임
모닥불에 완성된 음식이 남아 있음
침낭에서 수면이 진행 중임
반환 재료를 넣을 인벤토리 공간이 부족함
건축 데이터가 누락됨
반환할 재료 데이터가 누락됨
건축물의 StructureId가 유효하지 않음
11.4 철거 처리 순서
철거할 건축물의 데이터를 확인한다.
건축물의 StructureId가 유효한지 확인한다.
상위 건축물과 지지 관계를 확인한다.
기능별 철거 차단 조건을 확인한다.
반환할 재료와 수량을 계산한다.
반환 재료를 넣을 인벤토리 공간을 확인한다.
모든 반환 재료를 인벤토리에 추가한다.
기능별 저장 데이터를 제거한다.
지지 건축물의 연결점 사용 상태를 해제한다.
설치 건축물 저장 목록에서 제거한다.
월드에 배치된 건축물을 제거한다.
11.5 철거 실패 복구 규칙
반환 재료 중 하나라도 지급할 수 없으면 철거를 취소한다.
일부 재료만 반환된 경우 지급된 재료를 다시 회수한다.
철거가 취소되면 건축물을 제거하지 않는다.
철거가 취소되면 연결점 사용 상태를 변경하지 않는다.
철거가 취소되면 기능별 저장 데이터를 제거하지 않는다.
복구에 실패하면 오류를 출력하고 건축물을 유지한다.
