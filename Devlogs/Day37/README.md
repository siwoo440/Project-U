# Project U 개발 일지

---

## 37일차 : 침낭 부활 지점 저장 및 기상 후 자동 저장

### 개발 목표

침낭에서 수면해 등록한 부활 지점을 저장 파일에 기록하고, 게임을 다시 실행하거나 저장 데이터를 불러온 뒤에도 같은 침낭에서 부활할 수 있도록 저장 시스템을 확장했다. 수면이 끝난 다음 날 오전 8시의 상태를 자동으로 저장하도록 수면 시스템과 게임 저장 시스템도 연결했다.

### 구현 내용

- `RespawnSaveBridge`를 추가해 등록된 침낭의 `StructureId` 저장
- 부활 지점이 없는 미등록 상태 저장 및 복원
- 설치 건축물 복원 후 저장된 침낭의 `RespawnPoint` 재등록
- 저장된 침낭이 건축물 저장 목록에 존재하는지 검사
- 중복되거나 비어 있는 침낭 ID 검증
- 수면 연출 중 저장 및 불러오기 차단
- 수면 완료 후 체력·허기·갈증·날짜·시간 자동 저장
- 다음 날 오전 8시와 기상 완료 상태를 저장 지점으로 사용
- 기존 인벤토리·월드 아이템·채집 자원·건축물·모닥불 저장 기능 유지

### 저장 순서

1. 플레이어 상태와 게임 시간 수집
2. 인벤토리와 장비 수집
3. 월드 아이템과 채집 자원 수집
4. 설치 건축물과 모닥불 수집
5. 등록된 침낭 부활 지점 수집
6. JSON 저장 파일 생성

### 불러오기 순서

1. 저장 파일 읽기 및 데이터 검증
2. 인벤토리와 장비 복원
3. 월드 아이템과 채집 자원 복원
4. 설치 건축물과 모닥불 재생성
5. 저장된 `StructureId`와 일치하는 침낭 검색
6. 침낭의 `RespawnPoint` 재등록
7. 플레이어 상태와 게임 시간 적용

### 수면 후 자동 저장 흐름

1. 침낭 수면 시작
2. 화면 암전
3. 허기와 갈증 소비
4. 다음 날 오전 8시 적용
5. 체력 회복
6. 화면 밝아짐
7. 플레이어 조작과 수면 상태 복구
8. 기상 완료 상태 자동 저장

### 데이터 검증

- 부활 지점 등록 상태와 침낭 ID의 일치 여부 확인
- 등록 상태에서 비어 있는 침낭 ID 차단
- 미등록 상태에 남아 있는 침낭 ID 차단
- 건축물 저장 목록에 없는 침낭 ID 차단
- 동일한 `StructureId`가 중복된 저장 데이터 차단

### 테스트 결과

- 등록하지 않은 상태를 불러오면 기본 부활 위치 사용
- 등록한 침낭을 저장하고 불러오면 해당 부활 지점 복원
- Play Mode 재실행 후에도 침낭의 `StructureId` 유지
- 복원된 침낭에서 사망 후 정상 부활
- 다른 침낭 등록 시 이전 부활 지점 비활성화
- 등록된 침낭 철거 차단 유지
- 기상 후 날짜와 오전 8시 복원
- 기상 후 회복된 체력과 감소한 허기·갈증 복원
- 수면 연출 중 저장 및 불러오기 차단
- 기존 저장 기능 정상 작동
- Console 오류 없음

### 완료 결과

침낭 부활 지점이 설치 건축물 저장 데이터와 연결되었으며, 게임을 종료했다가 다시 실행해도 등록 상태를 유지한다. 저장 시점은 수면 전이 아니라 수면 처리가 모두 끝난 다음 날 오전 8시로 변경되었다.
