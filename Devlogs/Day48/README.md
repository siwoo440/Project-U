# 프로젝트 U 48일차 개발 일지

## 개발 목표

제작법마다 필요한 제작 시설과 해금 조건을 구분하고, 해금 상태를 저장·불러오기할 수 있는 기반 시스템을 구현했다.

## 개발 내용

### 제작 시설 및 해금 유형 정의

- 맨손, 작업대, 모닥불, 상급 작업대 제작 시설 구분
- 기본, 설계도, 퀘스트 제작법 해금 유형 구분
- 제작 시설별 고유 ID 정의

### 제작법 데이터 확장

- 제작법 데이터에 필요 제작 시설 추가
- 제작법 데이터에 해금 유형과 해금 조건 ID 추가
- 기본 해금 제작법 판정 기능 추가
- 기존 도끼와 곡괭이를 맨손 제작 및 기본 해금으로 설정

### 제작법 해금 시스템 구현

- 전체 제작법 등록 및 Recipe ID 중복 검사
- 기본 제작법 자동 해금
- Recipe ID를 이용한 제작법 해금
- 해금 상태 변경 이벤트 처리
- 등록되지 않은 제작법과 잘못된 설정 검증

### 제작 조건 및 UI 개선

- 잠긴 제작법 제작 차단
- 현재 시설과 필요 시설이 다를 때 제작 차단
- 해금, 시설, 재료, 인벤토리 공간을 종합한 제작 가능 여부 판정
- 제작 UI에 `LOCKED`, `WRONG FACILITY`, `NEED MATERIALS`, `INVENTORY FULL`, `READY` 상태 표시
- 제작법 해금 상태 변경 시 UI 자동 갱신

### 저장 및 불러오기 연동

- 해금된 제작법의 Recipe ID 목록 저장
- 저장된 제작법 해금 상태 복원
- 기존 저장 파일에서 기본 제작법 자동 해금
- 제작법 저장 데이터 누락, 빈 ID, 중복 ID 검사
- 저장 데이터 구조 검사 도구에 제작법 해금 항목 추가
- 저장 데이터 버전 1 유지

### 문서 수정

- 제작·보관·건축 규칙 문서의 닫히지 않은 코드 블록 수정
- 9.2~15번 항목의 Markdown 제목 형식 복원

## 테스트 결과

- 도끼와 곡괭이 기본 제작법 정상 표시
- 재료 보유량과 인벤토리 공간에 따른 제작 상태 정상 변경
- 제작 시설 불일치 상태 정상 표시
- 제작법 잠금 및 디버그 해금 정상 작동
- 해금 상태 저장 및 불러오기 정상 작동
- 기존 저장 파일 기본 제작법 호환 확인
- 저장 데이터 구조 검사 통과
- Unity Console 오류 없음

## 완료 결과

제작 시설과 제작법 해금 조건을 데이터로 관리할 수 있게 되었으며, 해금 상태가 저장 파일에 유지되도록 제작 시스템의 기반을 확장했다. 이후 작업대, 모닥불, 설계도 아이템 및 퀘스트 보상 시스템을 연결할 수 있는 구조가 마련되었다.
