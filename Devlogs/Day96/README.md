# Project U 개발 일지

## 96일차 : 전체 데이터 점검 도구(외형 연결·ID·깨진 참조·쓰이지 않는 데이터)와 도끼 외형 ID 수정

### 1. 개발 목표

95일차까지 콘텐츠와 숫자를 모두 넣었다. 데이터가 많아지면서 "아이콘이 빈칸", "떨어뜨리면 사라짐", "ID 글자가 달라 저장에서 빠짐" 같은 연결 문제가 생기기 쉬워졌다. 이번에는 **메뉴 한 번으로 전체 데이터의 연결을 점검하는 도구**를 만들고, 찾은 문제를 고쳤다. 99일차 빌드 점검 전에 쓰는 안전 장치다.

- 데이터 점검 도구와 결과 표 (`Docs/Audit/DataAudit.md`)
- 무기 외형 ID 규칙 수정 (도구 아이템도 무기 외형 사용)
- 도끼 외형 설정 ID · 이름 · 모델 수정
- 생성 메뉴(14번) · 검사

---

## 2. 데이터 점검 도구 (`DataAudit`)

`Assets/_ProjectU`의 데이터 152개 · Prefab 112개 · 게임 Scene 오브젝트를 한 번에 본다. **오류**는 꼭 고칠 것, **경고**는 확인할 것이다.

| 영역 | 점검 내용 |
| --- | --- |
| 아이템 | 아이콘(파일 이름 `ICON_아이템ID`), 바닥 Prefab(다른 아이템으로 설정되지 않았는지), 손에 든 외형(목록 · 도구 전용 · 활 전용), 저장 목록(ItemDatabase), 등록 목록(GameDataRegistry) |
| 연결 | 건축물 설치 · 미리보기 Prefab, 제작 · 요리 결과와 재료, 작물 단계 모델, 가축 모델 · 아이콘 · 먹이 · 생산물, 마을 NPC 초상, 적 전투 데이터 · 전리품 표 |
| ID | 12종류(아이템 · 제작법 · 요리법 · 건축물 · 적 · 작물 · 물고기 · 가축 · NPC · NPC 상점 · 보관함 · 외형 설정) : 규칙, 종류별 접두사, 같은 종류끼리 겹침, 다른 종류끼리 겹침, 등록 목록 누락 |
| 외형 설정 | Visual Profile ID가 분류 접두사(`visual_weapon_` 등)와 맞는지, 외형 Prefab이 있는지, 실제로 쓰는 Prefab이 있는지, Prefab이 가리키는 설정이 있는지 |
| 깨진 참조 | 스크립트가 사라진 컴포넌트, 지워진 파일을 가리키는 참조 (데이터 · Prefab · 게임 Scene) |
| 쓰이지 않음 | 아무도 참조하지 않는 데이터, 적이 쓰지 않는 전리품 표, 아이템이 쓰지 않는 아이콘 (ID로 찾는 작물 · 물고기 · NPC는 제외) |

- 결과 표 : 문제 목록 · ID 종류별 개수 · 외형 설정 목록(쓰는 곳) · 아이템 51종 외형 연결
- `Tools > Project U > Data Audit` : 고치지 않고 점검 표만 만든다.

## 3. 찾은 문제와 수정

| 찾은 것 | 원인 | 수정 |
| --- | --- | --- |
| 도끼 외형 설정(`visual_weapon_stone_axe`)을 쓰는 곳이 없고 찾을 수도 없음 | 도끼 아이템 ID는 `tool_axe`인데 무기 외형 규칙은 `item_` · `weapon_`만 받음. 받더라도 `visual_weapon_axe`가 되어 이름이 다름 | 무기 외형 규칙이 `tool_`도 받도록 수정, 설정을 `VP_Weapon_Axe` · `visual_weapon_axe`로 변경 |
| 도끼 외형 설정에 모델이 없음 (임시 상자 모양) | 설정만 만들고 모델을 연결하지 않음 | 돌도끼 저폴리 모델(`LP_tool_stone_axe`) 연결 |
| 밭(`structure_farm_plot`) 재료 없음 | 괭이로 땅을 바꾸는 설계 (정상) | 도구로 만드는 건축물은 재료 검사 제외 |

- 아이템 51종은 아이콘 · 바닥 Prefab · 손 외형 · 저장 목록 · 등록 목록이 모두 연결되어 있었다.
- 도끼 외형 설정은 이름만 바꾸고 GUID를 유지해서 등록 목록 연결이 그대로다.

남은 경고 (2개)

- `PF_Temp_Enemy_Basic` : 개발용 임시 적이라 전리품 표가 없다.
- `visual_weapon_axe` : 아직 쓰는 Prefab이 없다 (97일차 무기 외형에서 연결).

## 4. 생성 도구 · 검사

- `Tools > Project U > Build Content > 14. Data Audit Fixes (Visual IDs + Registry)`
  - 도끼 외형 설정 수정 → GameDataRegistry 등록 목록 다시 모으기 → 데이터 점검 → 점검 표 저장
  - 여러 번 실행해도 결과가 같다. Scene은 바꾸지 않는다.
- `Validate All Content`에 **데이터 점검** 검사를 추가했다 (오류 수만 셈, 도끼 외형 설정 ID 확인).

## 6. 남은 문제

- Registry Runtime은 00_Bootstrap Scene에만 있어서, 게임 Scene을 바로 Play하면 외형 설정을 ID로 찾는 기능은 쓸 수 없다 (지금은 Prefab에 연결된 설정을 씀).
- 외형 설정(Visual Profile)을 쓰는 것은 적 3 · 나무 아이템 · 나무 바닥뿐이고, 나머지는 저폴리 모델 교체 방식이다.
- 점검 도구는 Scene 하나(20_Gameplay)만 본다.
