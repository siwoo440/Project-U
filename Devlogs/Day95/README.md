# Project U 개발 일지

## 95일차 : 전체 콘텐츠 1차 밸런스 조정(계산 도구·반복 사냥·선물 제한·가격·보상) 구현

### 1. 개발 목표

94일차까지 생활(농사 · 낚시 · 요리 · 가축 · 판매)과 NPC(대화 · 상점 · 의뢰 · 이벤트)를 모두 넣었다. 이번에는 새 기능을 만들지 않고 **숫자를 다듬었다.** 데이터를 읽어 활동별 수입과 성장 속도를 계산하는 도구를 만들고, 목표에서 크게 벗어난 값을 찾아 고쳤다.

- 밸런스 계산 · 검사 도구와 결과 표 (`Docs/Balance/BalanceReport.md`)
- 반복 사냥 막기 (적 재생성 시간 · 전리품 확률)
- NPC 선물 한 주 2번 제한 (호감도 속도)
- 딸기 가격 · 송어 구이 · 의뢰 보상 조정
- 생성 메뉴(13번) · 검사

## 2. 밸런스 계산 도구 (`BalanceReport`)

게임 데이터(가격표 · 작물 · 물고기 · 가축 · 요리법 · 적 · 채집 자원 · 의뢰 · 호감도 규칙)를 읽어 계산한다. 시간은 실제 시간 기준이다 (하루 600초, 게임 1시간 = 25초).

| 항목 | 계산 | 목표 (벗어나면 오류) |
| --- | --- | --- |
| 농사 | 씨앗 1개 : 평균 수확 × 제철 가격 + 씨앗 돌려받기 - 씨앗 값, 자라는 날로 나눈 한 칸 하루 이익 | 작물마다 평균의 70~150%, 손해 없음 |
| 낚시 | 계절마다 맑은 날 연못 : 한 마리 평균 값 ÷ 한 마리 시간 (기다림 + 미니게임) | 다른 활동의 비교 기준 |
| 적 사냥 | 도끼로 쓰러뜨리는 시간 · 전리품 기대 값 · 다시 나오는 시간 → 1분 수입 | 낚시의 50% 이하, 재생성 게임 4시간 이상, 3~12번에 쓰러짐, 플레이어는 5번 이상 버팀, 자기 전리품 표 |
| 채집 | 자원 한 곳을 캐고 다시 나올 때까지 반복한 1분 수입 | 낚시 이하 |
| 가축 | 하루 생산물 값 - 하루 먹이 값, 데려오는 값을 되찾는 날 | 손해 없음 |
| 요리 | 요리 판매가 - 재료 판매가 | 요리하면 손해 없음 |
| 게시판 의뢰 | 보상 코인 ÷ 필요 물건 판매가 (그 계절 가격) | 1배 이상 (1.15배 아래는 참고 표시) |
| 호감도 | 매일 대화 + 선물(하루 · 한 주 제한) + 이벤트 최고 선택으로 단계에 닿는 날 | 아래 표 |
| 생존 | 깨어 있는 시간 + 잠잘 때 줄어드는 허기 · 갈증 | 하루 100 이하 |
| 큰 물건 | 100코인 이상 물건을 낚시 · 밭 10칸으로 모으는 시간 | 표만 |

### 호감도 목표

| 방법 | 목표 | 결과 |
| --- | --- | --- |
| 대화만 | 호기심 28일 안 | 20일 |
| 대화 + 좋아하는 선물 | 호기심 5~14일, 신뢰 35일 안 | 8일 · 15일 |
| 대화 + 매우 좋아하는 선물 | 호기심 4일 이후, 신뢰 8일 이후, 애정 42일 안 | 4일 · 9일 · 15일 |

- 계산 결과를 `Docs/Balance/BalanceReport.md` 표(활동별 수입 · 농사 · 낚시 · 적 · 가축 · 요리 · 의뢰 · 호감도 · 생존 · 큰 물건)로 남긴다.
- `Tools > Project U > Balance Report` : 값은 바꾸지 않고 표만 다시 만든다.

## 3. 찾은 문제와 조정

| 문제 (조정 전) | 조정 | 조정 후 |
| --- | --- | --- |
| 적이 10~15초마다 다시 나오고 전리품(섬유 · 버섯 · 철광석)이 모두 100% → 적 사냥이 1분 약 200코인으로 낚시(약 95)의 2배 | 근접 적 180초 · 원거리 적 240초마다 다시 나옴, 버섯 60% · 40%, 철광석 35% · 25%, 섬유 1~2개 | 1분 약 6.5코인 (낚시의 7%) |
| 원거리 적 Prefab이 근접 적 전리품 표를 씀 | 원거리 적 전리품 표 연결 | 적마다 자기 표 |
| 선물을 매일 줄 수 있어 매우 좋아하는 선물이면 3일 만에 호기심, 7일 만에 애정 | NPC 한 명에게 한 주(월~일) 2번까지, 생일 선물은 예외 | 호기심 4일 · 신뢰 9일 · 애정 15일 |
| 딸기 한 칸 하루 이익 3.1 (평균 5.0의 62%) | 판매가 5 → 7 | 5.2 |
| 송어 구이 : 송어(34)로 생선구이 1개(26) → 요리하면 손해 | 송어 1마리 → 생선구이 2개 | +18 |
| 베로나 의뢰 4개 · 밀키 호박 의뢰 보상이 판매가의 1.07~1.10배 | 베로나 감자 55 → 65 · 토마토 60 → 70 · 호박 75 → 90 · 겨울무 65 → 75, 밀키 호박 75 → 90 | 1.25배 이상 |
| 딸기 가격을 올리자 밀키 딸기 의뢰가 판매가보다 적어짐 | 50 → 60 (밀키 카페에서 사서 전달하는 값보다 높일 수 없음) | 1.11배 (참고) |

바꾸지 않은 것

- **배고픔 · 갈증** : 깨어 있는 동안 적게 줄지만 잠잘 때 15 · 20씩 줄어, 하루에 음식 1개 · 물 1개 정도가 필요하다. 지금 그대로 둔다.
- **낚시** : 1분 약 95코인으로 가장 잘 벌리지만, 계속 집중해야 하는 활동이라 이번에는 기준으로 두었다.
- **가축** : 닭 하루 10.5 · 소 14코인 이익, 1~2일이면 데려오는 값을 되찾는다.

## 4. 선물 한 주 제한

| 규칙 | 내용 |
| --- | --- |
| 하루 | NPC 한 명에게 하루 1번 (91일차) |
| 한 주 | 월~일 한 주에 2번, 월요일(1 · 8 · 15 … 일차)에 다시 채워짐 |
| 생일 | 한 주 제한 없이 줄 수 있고, 한 주 선물 수에 세지 않음 |

- 대화 창 선물 버튼 : `선물하기 (2)` → `선물하기 (1)` → 그날은 `선물 완료`, 한 주를 다 쓰면 `이번 주 완료`, 생일에는 `생일 선물`
- 막힌 이유 알림 : `이번 주에는 선물을 2번 받았어요. 월요일부터 다시 줄 수 있어요.`
- NPC 데이터베이스에 `giftsPerWeek`(2)를 추가했다.
- 저장 : 관계 기록에 `giftWeek`(마지막 선물 주) · `giftsThisWeek`(그 주 선물 수)를 추가했다. 95일차 이전 저장 파일은 "이번 주 선물 없음"으로 시작한다. 음수 값은 저장 검사에서 막는다.

## 5. 생성 도구 · 검사

- `Tools > Project U > Build Content > 13. Balance Pass (Prices + Loot + Respawn + Gifts)`
  - 요리법 다시 만들기(송어 구이 2개) → 판매 가격표(딸기) → 의뢰 데이터(CSV 보상) → 적 전리품 확률 → 원거리 적 전리품 표 연결 → NPC 선물 한 주 제한 → Scene 적 재생성 시간 → 밸런스 표 저장 → 검사
  - 여러 번 실행해도 결과가 같다.
- 요리 · 판매 생성 도구에 요리법만 · 가격표만 다시 만드는 기능(`RefreshRecipes` · `RefreshCatalog`)을 추가했다.
- 4번(요리) · 6번(판매) 메뉴의 원본 값도 함께 바꿔서, 다시 실행해도 조정이 유지된다.
- `Validate All Content`에 **밸런스** 검사를 추가했다 (계산 목표 + 조정 값이 적용되어 있는지).

## 7. 남은 문제

- 낚시 수입이 가장 높다 (작은 가방 450코인을 낚시 약 5분이면 모음). 2차 밸런스에서 입질 시간 · 물고기 가격을 다시 본다.
- 계산은 평균값 기준이다. 걷는 시간 · 미니게임 실패 · 날씨는 넣지 않았다.
- 나무 · 돌은 10초마다 다시 나온다 (1분 약 23코인으로 목표 안이라 그대로 둠).
- 밀키 딸기 의뢰는 카페 판매가 때문에 보상을 더 올릴 수 없다 (1.11배).
