# 프로젝트 U 31일차 개발 일지

---

## 개발 주제

**저장 데이터 구조와 버전 규칙 확정**

---

## 개발 목표

게임의 플레이어 상태, 시간, 인벤토리, 장비, 월드 오브젝트, 건축물과 부활 지점을 이후 저장 시스템에서 일관된 형식으로 처리할 수 있도록 공통 저장 데이터 구조를 구성했다.

실제 저장 파일 생성과 불러오기 기능을 연결하기 전에 JSON 직렬화 규격, 저장 버전 판정 규칙과 데이터 검증 기반을 먼저 확정했다.

---

## 구현 내용

### 1. 저장 버전 관리 규칙

- 현재 저장 형식 버전 `1` 정의
- 최소 지원 버전 `1` 정의
- 잘못된 버전 판정
- 지원이 종료된 이전 버전 판정
- 마이그레이션이 필요한 버전 판정
- 현재 버전 판정
- 게임보다 새로운 미래 버전 판정

### 2. 전체 저장 데이터 구조

- 저장 버전
- 저장 슬롯 ID
- UTC 기준 저장 시각
- 저장된 Scene 이름
- 플레이어 상태
- 날짜와 시간
- 인벤토리와 핫바
- 장비
- 월드 상태
- 부활 지점

### 3. 플레이어 및 생존 데이터

- 플레이어 위치와 회전
- 체력
- 허기
- 갈증
- 스태미나

### 4. 인벤토리 및 장비 데이터

- 실제 슬롯 번호
- 아이템 ID
- 아이템 수량
- 선택된 핫바 번호
- 장비 슬롯 종류
- 장착 아이템 ID

### 5. 월드 데이터

- 드롭된 월드 아이템
- 채집 자원의 남은 수량과 소진 상태
- 채집 자원의 재생성 대기 시간
- 설치 건축물의 고유 ID
- 건축 Recipe ID
- 건축물 위치와 회전
- 모닥불 조리 진행 상태와 남은 시간
- 침낭 부활 지점 등록 상태

### 6. 저장 데이터 검증

- 필수 저장 데이터 존재 여부 검사
- 저장 버전 유효성 검사
- 슬롯 ID, 저장 시각과 Scene 이름 검사
- 필수 데이터 묶음 검사
- 필수 목록 초기화 여부 검사
- 문제가 발생한 항목의 오류 메시지 반환

### 7. Unity Editor 검증 도구

Unity 상단 메뉴에 다음 검증 기능을 추가했다.

```text
Tools → Project U → Validate Save Data Schema
```

검증 도구에서 예제 저장 데이터를 JSON으로 변환한 뒤 다시 복원하여 다음 항목을 확인하도록 구성했다.

- 플레이어 데이터 복원
- 인벤토리 아이템 ID와 수량 복원
- 저장 데이터 유효성 검사
- 잘못된 버전 판정
- 미래 버전 판정
- 전체 JSON 구조 출력

## 저장 데이터 설계 원칙

- ScriptableObject 에셋 전체 대신 `ItemId`와 `RecipeId` 저장
- 기존 저장 필드 이름과 의미 유지
- 저장 구조의 호환성이 깨지는 변경 시 버전 증가
- 신규 필드는 이전 저장 데이터의 기본값 고려
- 월드 오브젝트와 설치 건축물에 중복되지 않는 고유 ID 사용
- `Vector3`와 `Quaternion`을 명시적인 저장용 데이터로 변환
