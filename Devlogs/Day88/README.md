# Project U 개발 일지

## 88일차 : 생활 콘텐츠 통합 점검과 에디터 메뉴 정리

### 1. 개발 목표

79~87일차에 만든 농사·낚시·요리·가축·판매를 하나의 하루 흐름으로 이어서 점검하고, 그동안 쌓인 에디터 메뉴를 정리했다.

이번 일차의 핵심 목표는 다음과 같다.

- 한 번 쓰고 끝난 도구와 중복 메뉴 삭제, 남은 메뉴를 `Tools > Project U` 하나로 모으기
- 기능별 검사와 기능 사이 연결 검사를 한 번에 하는 `Validate All Content` 추가
- 농사 → 낚시 → 가축 → 요리 → 판매 → 상인 → 저장·불러오기 통합 Play 점검
- 점검에서 찾은 문제 수정

---

## 2. 메뉴 정리 (87개 → 45개)

위쪽 메뉴 막대의 `Project U` 메뉴를 없애고 모두 `Tools > Project U` 아래로 옮겼다.

```text
Tools > Project U >
  Validate All Content
  Build Content > 1. Items ~ 6. Market
  Debug (Play Mode) > Give Life Starter Kit / Advance One Day (07:00) / Weather / 기능별 테스트
  Scene > Assign World Object IDs / Assign Enemy Spawn Point IDs
  Open Save Folder
```

| 지운 것 | 이유 |
| --- | --- |
| `ProjectUArtMenu` (Art & UI 실행·되돌리기 9개) | 78일차에 한 번 쓰고 끝난 작업, 되돌리기는 오히려 위험 |
| `ProjectUInspectorTooltipApplier` | 주석 → 툴팁 변환이 이미 끝남 |
| `SaveSchemaValidator`, `SaveFileSystemValidator` | 초기 저장 시험 도구, 기능별 저장 검사가 대신함 |
| `Project U/Visual` 선택 메뉴 8개 | 같은 기능이 Inspector 버튼에 있음 |
| 기능별 `Validate` 6개, 아이템 데이터·Registry 검사 메뉴 | `Validate All Content`로 합침 |
| 아이콘만 다시 만들기, 중복 다음 날 이동, 낚시 날씨 | 생성 도구 · 공통 Debug 메뉴로 합침 |

- 생성 도구는 메뉴 이름으로 Registry·월드 ID 메뉴를 부르던 방식을 함수 직접 호출로 바꿨다.
- 게임 안 오류 문구의 메뉴 경로도 새 경로(`Tools > Project U > Build Content > N. …`)로 고쳤다.
- 공통 Debug 메뉴(`ProjectUToolsMenu`)에 생활 시작 세트 지급(도구·씨앗·재료·코인), 다음 날 07:00, 날씨 바꾸기를 모았다.

## 3. 전체 콘텐츠 검사 (`Validate All Content`)

### 기능별 검사

아이템 외형 · 농사 · 낚시 · 요리 · 가축 · 판매 검사와 아이템 데이터 ID 규칙, Game Data Registry 검사를 차례로 실행한다. 오류가 있으면 문제 항목(✗ 줄)을 결과 창과 Console에 그대로 보여 준다.

### 생활 콘텐츠 연결 검사

| 검사 | 내용 |
| --- | --- |
| 생산물 판매 가격 | 작물 · 물고기 · 가축 생산물 · 요리가 모두 판매 가격표에 있는지 |
| 요리 재료 | 모든 재료를 수확 · 낚시 · 가축 · 제작 · 상인 · 채집 · 적 드롭 중 한 곳에서 구할 수 있는지 |
| 씨앗 | 작물의 재배 계절에 상인이 씨앗을 파는지, 계절마다 작물이 있는지 |
| 아이템 등록 | 저장용 ItemDatabase 누락, 바닥 드롭 Prefab 누락 |
| Scene | 건축 목록과 저장 목록 일치, 날짜 처리 관리자, 요리·우리·상인 창 연결, 저장 관리자 연결 |

## 4. 통합 Play 점검 (복사본 프로젝트)

| 단계 | 결과 |
| --- | --- |
| 농사 | 밭 3칸 갈기 · 심기 · 물주기, 4일째 감자 수확 |
| 낚시 | 송어 낚시 성공, 도감 1종 |
| 가축 | 닭 2마리 들이기 · 먹이, 매일 달걀 생산 |
| 요리 | 달걀 프라이 조리 |
| 판매 | 판매 상자 예상 +148 = 실제 판매 +148, 판매 알림 표시 |
| 상인 | 씨앗 3개 구매 후 다시 심기 |
| 저장·불러오기 | 저장 후 하루 넘기기 · 코인 비우기 · 동물 내보내기 → 불러오기 결과가 저장 시점과 일치 |
| 불러온 다음 날 | 중복 판매 없이 밭 성장 · 달걀 생산 계속 |
| 입력 잠금 | 모든 창을 닫은 뒤 0개 |

복사본의 제품 이름을 `Project U Copy Test`로 바꿔 테스트 저장 파일이 실제 저장 폴더와 섞이지 않게 했다.

## 5. 점검에서 찾은 문제 수정

- **아이템 ID 규칙 충돌** : 아이템 검사는 `item_wood` 등 7개를 오류로 봤지만 Registry는 `item_`을 권장했다. 저장 파일이 깨지지 않게 ID는 그대로 두고, 검사 규칙을 "분류별 접두사 또는 `item_`"로 맞췄다.
- **상호작용 안내 문구 줄바꿈** : `STRAWBERRY | DAY 4/5 | WATERED` 같은 긴 문구가 두 줄로 넘어가 가려졌다. 안내 상자가 문구 길이에 맞게 380~960px 사이로 넓어지도록 `PlayerInteractor`를 고쳤다.
- **GameManager 오류** : 게임 Scene을 바로 실행하면 뜨던 오류를 경고로 바꾸고, 화면의 `STATE: MANAGER MISSING` 글자를 숨겼다.
- **전체 검사 상세 표시** : 기능별 검사의 오류 줄이 전체 검사 결과에서 빠져 원인을 알 수 없었다. 문제 항목을 결과에 함께 표시하도록 고쳤다.
- **따뜻한 우유 Prefab** : 에디터에 남아 있던 예전 Prefab 연결 때문에 `WarmMilkPickup` 오류가 나왔고, Prefab을 다시 불러와 해결했다.

## 7. 남은 문제

- 복사본 테스트 중 복사본 설정 파일이 기본값으로 초기화되는 일이 있었다. 복사본을 쓸 때마다 패키지·설정 상태를 먼저 확인한다.
- 수확은 물뿌리개를 든 상태에서 상호작용해도 되는 현재 방식을 유지한다.
