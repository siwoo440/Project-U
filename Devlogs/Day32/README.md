## 32일차 : JSON 저장 파일 생성·읽기·백업 구현

### 개발 목표

31일차에 정의한 `SaveGameData` 구조를 실제 JSON 파일로 기록하고 다시 불러오는 파일 입출력 계층을 구현했다. 저장 도중 기존 데이터가 손상되는 상황을 줄이기 위해 임시 파일 검증과 이전 정상 파일 백업 절차를 추가했다.

### 주요 구현 내용

- `Application.persistentDataPath` 하위에 Project U 전용 저장 폴더 구성
- 슬롯 ID별 JSON 기본 저장 파일 생성
- BOM 없는 UTF-8 형식으로 JSON 기록
- 임시 `.tmp` 파일 기록 및 검증 후 기본 파일 교체
- 기존 정상 저장 파일을 `.backup.json`으로 보존
- 기본 파일 불러오기 실패 시 백업 파일 사용
- `SaveDataValidator`를 통한 저장 전·불러오기 후 데이터 검사
- 파일 이름과 내부 `saveSlotId` 일치 여부 검사
- 경로 문자 사용을 차단하는 슬롯 ID 유효성 검사
- Unity Editor 메뉴 기반 자동 검증 도구 추가
- 확인용 예제 저장 파일 생성 및 저장 폴더 열기 기능 추가

### 추가된 스크립트

| 파일 | 역할 |
|---|---|
| `Assets/_ProjectU/Scripts/Save/SaveFileService.cs` | JSON 저장·읽기·백업·복구와 슬롯 경로 관리 |
| `Assets/_ProjectU/Scripts/Editor/SaveFileSystemValidator.cs` | 파일 생성, 최신 데이터 복원, 손상 파일 감지와 백업 복구 자동 검사 |

### 저장 파일 구성

| 파일 | 용도 |
|---|---|
| `slot_01.json` | 현재 정상 저장 데이터 |
| `slot_01.backup.json` | 직전 정상 저장 데이터 |
| `slot_01.tmp` | 저장 작업 중에만 사용하는 임시 데이터 |

첫 저장에서는 기본 JSON 파일만 생성된다. 두 번째 저장부터 기존 정상 파일이 백업으로 보존되며, 저장이 끝난 뒤 임시 파일은 삭제된다.

### 저장 처리 흐름

1. 슬롯 ID와 저장 데이터 유효성 검사
2. 현재 저장 버전, 슬롯 ID, UTC 저장 시각 적용
3. 데이터를 JSON으로 변환해 임시 파일에 기록
4. 임시 파일을 다시 읽어 구조와 슬롯 ID 검사
5. 기존 기본 파일이 정상이면 백업을 만들면서 교체
6. 새 기본 파일을 다시 읽어 최종 검사
7. 남아 있는 임시 파일 정리

### 불러오기 및 복구 흐름

1. 기본 JSON 파일 존재 여부 확인
2. JSON 변환, 저장 버전, 필수 데이터와 슬롯 ID 검사
3. 기본 파일이 정상이면 최신 데이터 반환
4. 기본 파일이 없거나 손상됐다면 백업 파일 검사
5. 정상 백업이 있으면 백업 데이터 반환
6. 두 파일이 모두 잘못됐다면 원인을 포함한 실패 결과 반환

### 슬롯 ID 규칙

슬롯 ID에는 문자, 숫자, 밑줄과 하이픈만 사용할 수 있도록 제한했다. `../slot_01`, `slot/01`, `slot\01`과 같은 값은 저장 폴더 밖의 경로로 해석될 수 있으므로 차단한다.

### 검증 결과

`Tools → Project U → Validate Save File System` 메뉴를 통해 다음 항목을 검사했다.

- 첫 번째 저장 파일 생성
- 두 번째 저장 시 백업 파일 생성
- 최신 기본 파일의 데이터 복원
- 기본 파일을 의도적으로 손상시킨 뒤 백업 데이터 복원
- 테스트용 임시·기본·백업 파일 정리
- 저장 완료 후 `.tmp` 파일 미잔류
- 기존 이동·채집·건축·조리·수면·부활 기능 유지
- Console 컴파일 오류 및 실행 오류 없음
