# Project U 개발 일지

## 92일차 : NPC 상점 판매 목록·가격·영업 시간·재고·사고팔기 구현

### 1. 개발 목표

91일차에는 대화 창의 거래 버튼이 가판대의 리첼만 87일차 상인 창으로 연결됐다. 이번에는 상인 역할 NPC 3명에게 각자 가게를 주고, 대화 창에서 바로 사고팔 수 있게 만들었다.

- 밀키(선셋 카페) · 드라비아(대장간) · 리첼(떠돌이 상점)의 판매 목록과 가격을 데이터로 정하기
- 영업 시간 · 휴무일은 NPC 일정 데이터를 그대로 사용
- 하루 재고와 날짜가 바뀔 때 재고 채우기
- 사기뿐 아니라 NPC에게 팔기 (가게마다 사 주는 물건이 다름)
- 호감도 단계에 따른 할인과 잠긴 물건
- 87일차 상인 창(`ShopPopupUI`)을 다시 사용
- 저장 · 생성 메뉴(10번) · 검사

### 파는 물건

- 87일차 떠돌이 상인이 팔던 물건은 리첼이 이어서 판다. 철광석은 드라비아의 대장간으로 옮겼다.

### 사 주는 물건 (플레이어가 팔기)

값은 판매 상자 가격(제철 가격 포함)에 가게 배율을 곱해서 정한다. 판매 상자 가격표에 없는 도구 · 장비는 팔 수 없다.

| 가게 | 사 주는 물건 | 하루 최대 |
| --- | --- | --- |
| 밀키 | 작물 · 채집물 100%, 가축 생산물(우유 · 달걀) 110% | 30개 |
| 드라비아 | 철광석 120%, 돌 · 나무 100% | 20개 |
| 리첼 | 팔 수 있는 물건 전부 80% | 40개 |

- 판매 상자는 자정에 팔리지만, NPC 가게는 영업 시간 안에 바로 코인을 받는다.
- 하루 매입 수를 넘으면 `ONLY 27 MORE TODAY`, `NO MORE BUYING TODAY`로 막는다.

### 호감도 할인

| 단계 | 무관심 | 호기심 | 신뢰 | 애정 | 사랑 |
| --- | --- | --- | --- | --- | --- |
| 할인 | 0% | 0% | 5% | 10% | 15% |

- 필요한 단계가 안 되는 물건은 목록에 `'신뢰' 단계부터 살 수 있어요`로 보이고 살 수 없다.

## 3. 영업 시간 · 휴무일 (`NpcShopManager`)

영업 시간을 따로 적지 않고, 주인의 일정에서 영업 위치(카페 카운터 · 대장간 모루 · 상인 가판대)에 있는 시간을 영업 시간으로 쓴다. 일정을 바꾸면 영업 시간도 같이 바뀐다.

| 가게 | 맑은 날 영업 시간 | 휴무 |
| --- | --- | --- |
| 밀키 | 08:00 ~ 18:00 | 수요일 |
| 드라비아 | 09:00 ~ 13:00, 14:00 ~ 18:00 (점심 13시 카페) | 일요일 |
| 리첼 | 06:00 ~ 20:00 | 없음 (가판대가 있어야 장사) |

- 거래할 수 있는 조건 : 일정상 영업 시간 + 주인이 영업 위치에 도착 + (리첼) 상인 가판대가 있음
- 닫혀 있으면 이유와 다음 영업 시각을 알려 준다.
  - `오늘 영업은 끝났어요. 내일 08:00에 열어요.`
  - `오늘은 쉬는 날이에요. 내일 09:00에 열어요.`
  - `지금은 영업 시간이 아니에요. 14:00에 열어요.`
  - `가게로 가는 중이에요. 도착하면 거래할 수 있어요.`
  - `가판대가 있어야 물건을 펼칠 수 있어요. 상인 가판대를 지어 주세요.`
- 다음 영업일은 7일 안에서 찾고, 앞날 날씨는 알 수 없으니 맑은 날 기준으로 계산한다.

### 재고

- 날짜가 바뀌면 모든 가게의 재고와 하루 매입 수를 다시 채운다.
- 같은 날이면 항상 같은 재고가 나온다 (날짜 + 가게 기준 값으로 뽑기).
- 계절이 맞는 물건만 나오고, 확률이 1보다 작은 물건은 그날 들어올 때만 나온다 (`RARE FIND`).

## 4. 상점 창 (87일차 `ShopPopupUI` 재사용)

87일차 상인 창을 그대로 쓰면서, 창이 보여 줄 가게를 `IShopVendor`로 나눴다.

| 가게 종류 | 연결 | 두 번째 탭 |
| --- | --- | --- |
| NPC 상점 | `NpcShopVendor` | SELL (팔기) |
| 가판대 기본 상인 (마을 NPC가 없는 Scene) | `StallShopVendor` | SELL PRICES (87일차 판매 가격표) |

```text
[밀키 초상] 밀키 · 선셋 카페      [영업 08:00 ~ 18:00 · 신뢰 할인 5%] [코인] [ESC]
[ BUY (9) ] [ SELL (2) ]  TAB          "좋은 달걀이나 우유가 있으면 저한테 팔아 줘요."
[목록 : 이름 · 5% OFF · 4 LEFT · 가격]   [상세 : 가격 (할인 전 가격 줄 긋기) · 수량 · BUY / SELL]
```

- 제목 아이콘은 91일차 NPC 초상, 제목 옆에 그날의 인사 한마디가 나온다.
- 팔기 탭에는 가방에서 그 가게가 사 주는 물건만 보이고, 판매 상자 가격과 비교해 보여 준다 (`+12% VS BIN`, `SAME AS SHIPPING BIN`).
- 창이 열려 있는 동안 주인은 멈춰서 플레이어를 바라본다.
- 영업 시간이 끝나면 마감 인사(`오늘 영업은 여기까지예요~ 내일 또 와요.`)를 띄우고 창을 닫는다.
- 플레이어가 4.5m 넘게 멀어지거나 주인이 집에 들어가면 창을 닫는다.
- 탭 · 수량 · Shift 10개 · 알림 등 나머지 조작은 87일차와 같다.

### 여는 방법

- 대화 창 `거래` 버튼 : 대화 창에서 바로 상점 창으로 넘어간다. 닫혀 있으면 버튼이 `거래 (닫힘)`이 되고, 누르면 이유와 오늘 영업 시간을 알려 준다.
- 안내 문구 : 영업 중인 주인에게 다가가면 `F - 밀키 | 대화 · 거래`
- 상인 가판대 : 리첼이 서 있으면 `F - TRADE (리첼)`로 리첼의 상점을 연다.

## 5. 저장 (`NpcShopSaveBridge`)

```text
hasNpcShopData
npcShops { shops[] { shopId, stockDay, stock[] { itemId, remaining },
                     buybackDay, boughtFromPlayer, totalCoinsSpent, totalCoinsEarned } }
```

- 같은 날 저장이면 남은 재고와 오늘 매입 수를 복원하고, 다른 날이면 새 재고로 시작한다.
- 지난 날짜의 매입 기록은 저장하지 않는다.
- 코인은 87일차 상점 저장을 그대로 쓴다.
- 92일차 이전 저장 파일은 그날 재고로 시작한다.
- 검사 : 상점 ID(`shop_`), 상점 중복, 재고 아이템 중복, 음수 · 너무 큰 값

## 7. 생성 도구 · 테스트 메뉴

- `Tools > Project U > Build Content > 10. NPC Shops (Stock + Prices + Hours + Trade)`
  - 원본 CSV → 가게 데이터 3개 → 한글 글꼴 확인 → NPC 관리자에 상점 관리자 추가 → 상인 창 다시 생성(한마디 칸) → 검사
  - 여러 번 실행해도 결과가 같다.
- `Debug (Play Mode) > NPC`
  - Log NPC Shops (영업 상태 · 재고 · 할인 · 매입 남은 수)
  - Refresh NPC Shop Stock (Today)
  - Open Nearest NPC Shop
- `Validate All Content`에 **NPC 상점** 검사를 추가했다.
  - 가게 3곳, 주인의 상점 ID · 상인 역할 · 거래 상호작용
  - 영업 위치가 NPC 위치 목록 · Scene에 있는지, 계절마다 영업하는 날이 있는지
  - 판매 목록 중복 · 확률, 계절마다 매일 파는 물건 3종 이상
  - 되팔기 이익 없음 (가장 싸게 산 값 > 판매 상자 · 모든 가게 매입 값)
  - 작물마다 재배 계절에 씨앗을 파는 가게가 있는지
  - 할인율 범위, 매입 규칙, 한글 글꼴 글자, Scene 연결
- 전체 콘텐츠 검사의 "구하는 곳"에 NPC 상점 물건을 포함했다.

## 9. 남은 문제

- 상점 창의 기본 문구(BUY · SELL · LEFT 등)는 87일차처럼 영어이고, NPC 이름 · 인사 · 닫힌 이유만 한국어다.
- 닫힌 거래 버튼은 문구만 `거래 (닫힘)`으로 바뀌고 색은 그대로다.
- 다음 영업일 안내는 맑은 날 기준이라, 비 오는 날 일정이 다르면 실제와 조금 다를 수 있다.
- 가게에서 사고판 기록(`Traded` 이벤트)은 아직 쓰는 곳이 없다 (93일차 의뢰에서 사용 예정).
