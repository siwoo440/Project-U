# Project U 개발 일지

---

## 35일차 : 월드 아이템 및 채집 자원 저장·복원

### 개발 목표

기존 저장 시스템을 확장하여 인벤토리와 플레이어 상태뿐만 아니라 월드에 배치된 아이템과 채집 자원의 상태도 저장하고 복원할 수 있도록 구현했다.

### 주요 구현 내용

- 월드 아이템과 채집 자원을 구분하는 고유 ID 시스템 구현
- Scene에 배치된 월드 오브젝트의 ID 자동 발급 및 중복 검사 도구 추가
- 월드 아이템의 아이템 ID, 수량, 위치, 회전 저장
- 획득 완료한 기본 월드 아이템의 비활성 상태 유지
- 플레이어가 버린 동적 월드 아이템 저장 및 재생성
- 채집 자원의 남은 수량과 소진 상태 저장
- 채집 자원의 재생성까지 남은 시간 저장
- 저장 당시 월드 상태를 같은 Play Mode와 Play Mode 재실행 후 모두 복원
- 기존 인벤토리, 장비, 플레이어 상태, 위치, 카메라, 날짜와 시간 저장 기능 연동

### 추가 및 수정된 주요 스크립트

- `SaveDataSchema.cs`
  - 월드 저장 데이터 구조 추가
  - 월드 아이템과 채집 자원 저장 항목 정의
- `WorldObjectIdentity.cs`
  - 월드 오브젝트별 고유 ID 관리
- `WorldItemPickup.cs`
  - 월드 아이템의 저장 상태 조회 및 복원 기능 추가
  - 전체 획득 시 제거 대신 비활성화 처리
- `GatherableResource.cs`
  - 남은 자원 수량과 소진 상태 복원 기능 추가
  - 재생성 남은 시간 저장 및 재개 기능 추가
- `WorldSaveBridge.cs`
  - 월드 아이템과 채집 자원의 상태 수집 및 복원
  - 저장 데이터와 Scene 오브젝트 검증
- `WorldObjectIdValidator.cs`
  - 월드 오브젝트 ID 자동 발급
  - 빈 ID와 중복 ID 검사 및 수정
- `GameplaySaveController.cs`
  - 월드 상태 저장 및 불러오기 순서 연결

### Unity 설정

- `20_Gameplay` Scene의 월드 아이템과 채집 자원에 고유 ID 발급
- `=== SaveSystem ===` 오브젝트에 `WorldSaveBridge` 추가
- `ItemDatabase.asset`, `WorldItemDrop.prefab`, `WorldItems` 부모 연결
- `GameplaySaveController`에 `WorldSaveBridge` 참조 연결

### 테스트 결과

- 저장 전에 획득한 기본 월드 아이템이 불러오기 후 다시 나타나지 않음
- 저장 당시 남아 있던 기본 월드 아이템의 상태 복원
- 플레이어가 버린 아이템의 위치, 회전, 수량 복원
- 저장 후 추가로 획득한 아이템이 저장 시점 상태로 복귀
- 동일한 월드 아이템이 중복 생성되지 않음
- 채집 자원의 남은 수량 복원
- 완전히 소진된 채집 자원의 외형과 Collider 상태 복원
- 저장 당시 남은 재생성 시간부터 대기 재개
- Play Mode 종료 후 다시 실행해도 월드 상태 복원
- 기존 인벤토리, 장비, 플레이어 상태, 게임 시간 저장 기능 정상 유지
- Console 오류 없음

### 이번 일차 제외 범위

- 설치 건축물 저장 및 복원
- 모닥불 조리 상태 저장 및 복원
- 침낭 부활 지점 저장 및 복원
- 여러 Scene의 월드 상태 동시 관리
- 게임 종료 중 실제 경과 시간을 반영한 자원 재생성
- Rigidbody 이동 속도 저장
- 아이템별 내구도와 품질 저장
- 자동 저장과 시작 시 자동 불러오기
- 저장 슬롯 선택·삭제 UI
- 구버전 월드 데이터 변환

### 완료 결과

35일차 작업을 통해 월드에 존재하는 아이템과 채집 자원이 저장 시점의 상태로 복원되도록 저장 시스템의 범위를 확장했다. 기본 배치 아이템, 플레이어가 버린 동적 아이템, 부분 채집 자원, 소진 및 재생성 대기 중인 자원까지 동일한 고유 ID를 기준으로 관리할 수 있다.
