# Project U 개발 일지

---

## 36일차 : 설치 건축물 및 모닥불 상태 저장·복원

### 개발 목표

기존 저장 시스템을 확장하여 플레이어가 설치한 건축물과 모닥불의 조리 상태를 저장하고, 저장 당시의 위치와 진행 상태로 정확하게 복원할 수 있도록 구현했다.

### 주요 구현 내용

- 설치된 나무 바닥, 나무 벽, 모닥불, 침낭의 상태 저장
- 설치 건축물마다 런타임 고유 ID 발급
- 건축 레시피 ID를 이용한 설치 프리팹 식별
- 건축물의 월드 위치와 회전 저장
- 저장 후 설치한 건축물 제거 및 저장 후 철거한 건축물 재생성
- 모닥불의 조리 진행 여부 저장
- 모닥불에 완성된 음식이 남아 있는 상태 저장
- 조리 완료까지 남은 시간 저장 및 복원
- 이전 저장 파일과의 호환성을 위한 건축물 상태 수집 여부 추가
- 기존 인벤토리, 월드 아이템, 채집 자원, 플레이어 상태 및 시간 저장 기능과 연동

### 추가 및 수정된 주요 스크립트

- `SaveDataSchema.cs`
  - 설치 건축물 상태 수집 여부 추가
  - 모닥불 추가 상태 존재 여부 추가
- `PlacedBuildObject.cs`
  - 설치 건축물 고유 ID 관리
  - 저장 데이터 기반 건축물 복원 기능 추가
- `CampfireCookingStation.cs`
  - 조리 진행 상태와 완성 음식 상태 공개
  - 남은 조리 시간 복원 기능 추가
- `PlacedStructureSaveBridge.cs`
  - 설치 건축물 상태 수집 및 복원
  - 건축 레시피와 고유 ID 검증
  - 모닥불 조리 상태 저장 및 복원
- `GameplaySaveController.cs`
  - 설치 건축물 저장 연결 참조 추가
  - 건축물 상태 저장 및 불러오기 순서 연결

### Unity 설정

- `=== SaveSystem ===` 오브젝트에 `PlacedStructureSaveBridge` 추가
- `Placed Structure Parent`에 `PlacedObjects` 연결
- 나무 바닥, 나무 벽, 모닥불, 침낭의 `BuildRecipeData` 등록
- `GameplaySaveController`에 `PlacedStructureSaveBridge` 참조 연결
- 건축물 프리팹에 `WorldObjectIdentity` 구성

### 테스트 결과

- 저장 당시 설치된 바닥, 벽, 모닥불, 침낭 복원
- 건축물의 저장 당시 위치와 회전 유지
- 저장 후 새로 설치한 건축물 제거
- 저장 후 철거한 건축물 재생성
- 건축물별 고유 ID 유지 및 중복 생성 방지
- 조리 중인 모닥불의 남은 시간 복원
- 조리 중 불꽃 연출과 진행 상태 복원
- 완성 음식을 회수하지 않은 모닥불 상태 복원
- 복원된 완성 음식을 한 번만 회수 가능
- Play Mode 재실행 후에도 건축물과 모닥불 상태 복원
- 기존 월드 아이템과 채집 자원 저장 기능 정상 유지
- 기존 인벤토리, 장비, 플레이어 상태, 위치 및 게임 시간 저장 기능 정상 유지
- Console 오류 없음

### 이번 일차 제외 범위

- 침낭에 등록된 부활 지점 저장 및 복원
- 침낭 수면 진행 상태 저장
- 건축물 내구도와 피해 상태 저장
- 건축물 내부 보관함 상태 저장
- 건축물 이동 기능
- 여러 Scene의 건축물 동시 저장
- 게임 종료 중 실제 경과 시간을 반영한 조리
- 자동 저장과 시작 시 자동 불러오기
- 저장 슬롯 선택 및 삭제 UI

### 완료 결과

36일차 작업을 통해 플레이어가 설치한 건축물이 저장 시점의 종류, 위치, 회전으로 복원되도록 저장 시스템의 범위를 확장했다. 모닥불은 조리 중인 상태와 완성 음식 보관 상태를 구분하여 저장하며, 남은 조리 시간부터 정상적으로 진행을 재개한다.

### 다음 개발 방향

37일차에는 침낭에 등록한 부활 지점과 수면 이후의 플레이어 상태를 저장·복원하고, 저장 데이터의 전체 검증 범위를 확장한다.
