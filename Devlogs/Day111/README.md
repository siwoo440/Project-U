# Project U 개발 일지

## 111일차 : 4차 NPC 이야기 (의뢰 · 하트 이벤트) · 공정한 게시판 · Tools 정리와 콘텐츠 자동 적용

### 1. 개발 목표

110일차에 섬에 들어온 4차 NPC 7명에게 **의뢰와 하트 이벤트**를 붙여 이야기 차수로 올렸다. 그러자 잠겨 있던 동료 후보(라그 · 켄시아 · 에이리)가 풀렸다.
추가 작업으로 **Tools 메뉴를 정리**하고, 앞으로는 메뉴를 누르지 않아도 새 콘텐츠가 **자동으로 적용**되게 했다.

## 4. 공정한 게시판 (`NpcQuestManager`)

- 문제 : 의뢰하는 NPC가 28명인데 게시판은 하루 3칸, 순전히 무작위라 한 달 내내 안 나오는 NPC가 있었다 (점검에서 노크티아).
- 해결 : 날짜를 한 바퀴(NPC 수 ÷ 3 = 약 10일)로 묶고, 바퀴마다 NPC 순서를 섞어 '오늘 차례'인 NPC의 의뢰를 먼저 올린다. 같은 날이면 항상 같은 게시판이고, 특별 의뢰가 먼저인 규칙과 하루 칸 수 · 보상은 그대로다.

## 5. Tools 정리

- 삭제한 메뉴 : 번호 메뉴 25개(1 ~ 25번 만들기), Validate All Content, Balance Report, Data Audit, Scene ID 발급 2개
  - 확인 창을 띄우던 메뉴 코드와 그 메뉴에서만 쓰던 도우미를 지웠다 (32개 파일, 약 800줄).
  - 만드는 코드(`BuildAll` · `Validate`)는 남겼다. 자동 적용과 검사가 이 코드를 부른다.
- 남긴 메뉴 : `Debug (Play Mode)` 치트 메뉴, `Build/Windows Alpha Build`, `Open Save Folder`

## 6. 콘텐츠 자동 적용 (`ProjectUAutoContent`)

1. Unity를 열거나 컴파일이 끝나면 `Updates` 목록에서 아직 적용하지 않은 항목을 찾는다.
2. 게임 Scene을 열어 차례대로 실행 → Scene · Asset 저장 → 전체 콘텐츠 검사
3. 적용 기록을 `ProjectSettings/ProjectUContentState.json`에 남겨 다시 하지 않는다 (커밋).
4. 결과는 Console · `Logs/ProjectU_AutoContent.log`에 남고, 원래 열려 있던 Scene으로 돌아간다. 저장하지 않은 Scene이 있을 때만 저장할지 묻는다.

- 111일차 21번 메뉴는 이미 직접 실행해서 "적용 완료"로 기록해 두었다.
